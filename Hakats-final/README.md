# TechArena: агент для решения задач

Это наш проект для соревнования TechArena. Агенту дают папку с задачами (math, data, search и coding),
а он должен решить как можно больше из них и уложиться в бюджет токенов. Агент построен на
openJiuwen (`openjiuwen==0.1.16`) и JiuwenSwarm (`jiuwenswarm==0.2.3`), модель по умолчанию
`qwen3.8-27b-noreason`.

## Идея

Баллы дают за решённые задачи, а токены стоят денег. Поэтому мы старались, чтобы модель
вызывалась только там, где без неё никак. Многое агент решает обычным кодом, совсем без токенов,
а модели остаются только задачи, которые так не решить.

## Как запустить

Через Docker:

```bash
docker build -t hack:latest .
docker run --rm --network hack-net \
  -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 8 --memory 16g --pids-limit 512 \
  --workdir /app --entrypoint python \
  hack:latest /app/run_agent.py --tasks-dir /data/tasks
```

Без Docker (Python 3.12):

```bash
pip install -r requirements.txt
LLM_BASE_URL=... LLM_API_KEY=... python run_agent.py --tasks-dir path/to/tasks --out runs/results.json
```

Ответ на решённую задачу появляется в `<задача>/answer.txt` рядом с `task.json`. У невыполнимых
и нерешённых задач этого файла нет.

## Как работает агент

1. **Смотрим на задачи.** Для каждой задачи `harness/observe.py` собирает короткое описание папки:
   заголовок и первые строки CSV, формат записей базы знаний, исходники и вывод видимых тестов.
   Здесь же видно часть невыполнимых задач: нет нужного файла, тест импортирует несуществующий
   модуль или два теста противоречат друг другу.
2. **Решаем без модели.** В `harness/rules/` лежат строгие разборщики типовых формулировок:
   складская арифметика, агрегаты по CSV и цепочки ссылок в базе знаний. Если хотя бы одно
   предложение не распознано, разборщик отказывается, и задача идёт дальше. Для coding
   `code_repair.py` перебирает мелкие правки кода (поменять знак, сравнение, константу на единицу)
   и оставляет ту, с которой проходят все видимые тесты.
3. **Выбираем порядок.** `harness/planner.py` оценивает стоимость и шанс решить каждую задачу и
   сортирует их по ожидаемым баллам на единицу бюджета. Оценки обучены на наших прогонах
   (`harness/cost_model.json`).
4. **Спрашиваем модель.** Остальные задачи решает `harness/solver.py` в коротком разговоре
   с моделью. Модель отвечает строкой `CHECK`, потом скриптом на питоне, ответом `ANSWER:` или
   правками кода. Данные для скрипта уже загружены заранее (`harness/preludes.py`), поэтому
   скрипты получаются в несколько строк. Частые ошибки в ответах модели `harness/replies.py`
   исправляет сам, чтобы не тратить на них лишний вызов.
5. **Сохраняем.** После каждой задачи файл с результатами переписывается заново, так что при
   остановке готовые ответы не пропадают.

Все действия агента оформлены как инструменты openJiuwen (`harness/tools.py`), а модель
вызывается через клиент `Model` из openJiuwen (`harness/llm.py`).

## Бюджет

Расход считается как выходные токены плюс входные, делённые на 10. Общий бюджет приходит
в переменной `BUDGET`, а если её нет, берём 100000. Агент планирует на 95% бюджета, а дорогие
дополнительные шаги (перепроверка coding и попытка на модели с рассуждениями) включает только
пока потрачено немного.

## Траектории

Рядом с файлом результатов (`--out`, по умолчанию `$HOME/techarena_results.json`) агент сохраняет:

- сам файл результатов: по каждой задаче статус, ответ, потраченные токены, прогноз планировщика
  (стоимость, шанс решить, признак невыполнимости) и причину, если задачу пропустили;
- `calls.jsonl`: по строке на каждый вызов модели, с моделью, входными и выходными токенами,
  стоимостью вызова и накопленным расходом по задаче и по прогону, задержкой и кодом ответа;
- `trajectories/<задача>.json`: полный разговор с моделью по задаче, с итоговым статусом, ответом
  и стоимостью. Для задач, решённых без модели, такого файла нет.

На этих данных мы обучали оценки в `harness/cost_model.json` и разбирали ошибки. Чтобы забрать их
из контейнера, достаточно смонтировать папку и передать путь, например
`-v "$PWD/out:/data/out" ... --out /data/out/results.json`.

## Структура

| Файл | Что делает |
| --- | --- |
| `run_agent.py` | точка входа: загружает задачи, выстраивает очередь, решает до 5 задач параллельно |
| `harness/config.py` | переменные окружения для openJiuwen и JiuwenSwarm |
| `harness/observe.py` | описание папки задачи, запуск тестов, предпроверки |
| `harness/rules/` | решатели без токенов и починка кода перебором |
| `harness/router.py` | перевод задачи в спеку для точного решателя (по умолчанию выключен) |
| `harness/planner.py` | оценка стоимости и порядок задач |
| `harness/solver.py` | решение одной задачи, системный промпт |
| `harness/replies.py` | разбор ответов модели |
| `harness/preludes.py` | загрузка данных перед скриптом модели |
| `harness/workspace.py` | запуск скриптов и применение правок |
| `harness/tools.py` | инструменты openJiuwen |
| `harness/llm.py` | вызовы модели, повторы, учёт бюджета |
| `harness/telemetry.py` | запись `calls.jsonl` |
| `harness/netblock/` | запрет сети для тестов |

## Настройки

- `AGENT_MODEL` выбирает модель, по умолчанию `qwen3.8-27b-noreason`.
- `MAX_PARALLEL` задаёт число задач одновременно, по умолчанию 5.
- `BUDGET` задаёт общий бюджет в единицах.

## Что получилось

На восьми примерах задач агент набирает 20 из 20 баллов и тратит около 200 единиц: семь задач
решаются без модели, на последнюю уходит пара коротких вызовов. На наших наборах по 100 задач
он набирает около 95% баллов и тратит примерно 30k единиц. Некоторые идеи не окупились, и мы их
выключили: второй проход по нерешённым задачам, повторное решение с голосованием и модель
с рассуждениями в роли основной. Они давали столько же баллов, но тратили заметно больше токенов.
